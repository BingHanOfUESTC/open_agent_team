## 2. 分阶段时间线

### Phase 0: Transformer 诞生 (2017)

**核心研究问题**: 机器翻译能否摆脱 RNN/LSTM 的顺序计算瓶颈？

| 论文 ID | 标题 | 核心贡献 | 影响力级别 |
|---------|------|---------|-----------|
| 2.1.1 | Attention Is All You Need (Vaswani et al., Google Brain, 2017) | 提出完全基于自注意力的 Transformer 架构，定义了 Multi-Head Attention、Positional Encoding、Layer Norm 等核心组件 | **范式转变**: 彻底改变了 NLP 和后续整个深度学习的架构设计 |

**关键观察**: Transformer 最初设计为 **编码器-解码器 (Encoder-Decoder)** 架构用于机器翻译。论文中 Base (65M) 和 Big (213M) 两个尺度的设置，首次展示了模型缩放的可能性。这篇论文是 LLM 整个技术树的根节点——从它分叉出了 Encoder-Only（BERT）、Decoder-Only（GPT）和 Encoder-Decoder（T5）三条主要路径。

---

### Phase 1: 预训练范式确立 (2018–2019)

**核心研究问题**: 如何在标注数据稀缺的情况下获得高质量的语言表示？预训练+微调能否成为 NLP 的通用范式？

#### 1A. 过渡性先驱

| 论文 ID | 年份 | 核心贡献 |
|---------|------|---------|
| 2.1.2 (ULMFiT) | 2018 | 提出通用语言模型微调三阶段方法（通用预训练 → 任务特定微调 → 分类器微调），是迁移学习在 NLP 中的关键先驱。discriminative fine-tuning 和 slanted triangular learning rates 是后来的 BERT/GPT 微调的思想前身。 |

#### 1B. Decoder-Only 路线：GPT 系列起航

```
GPT-1 (2.2.1) ──→ GPT-2 (2.2.3)
  2018              2019
  117M              1.5B
  半监督学习          零样本多任务

关键转变:
  GPT-1: "pre-training + supervised fine-tuning"（预训练+有监督微调）
  GPT-2: "语言模型即多任务学习器"（展示零样本泛化，强调"不需要微调"）
```

**GPT-1 → GPT-2 的范式跃迁**:
- GPT-1 证明了大规模无监督预训练对下游任务的增益
- GPT-2 进一步提出激进主张：足够大的语言模型可以**零样本**完成多种任务，微调可能不再必要
- GPT-2 的 1.5B 参数在当时被认为"太大而不敢发布"，直接引发了关于 AI 安全和大规模部署的讨论
- WebText 数据集首次强调**数据质量过滤**（仅保留高质量 Reddit 链接），这一理念贯穿了后续所有 GPT 系列

#### 1C. Encoder-Only 路线：BERT 家族

```
                                             ┌──→ RoBERTa (2.2.4, 2019)
                                             │    复现+改进: 更多数据、更长训练
                                             │    证明 BERT 远未被充分训练
                                             │
BERT (2.2.2, 2018) ──┬──────────────────────┤
Google               │                      ├──→ ALBERT (2.2.7, 2019)
110M/340M            │                      │    参数共享+嵌入分解: 大幅降低参数量
MLM + NSP            │                      │
                     │                      └──→ XLNet (2.2.8, 2019)
                     │                           排列语言建模: 融合自回归与双向优势
                     │
                     └──→ [DeBERTa, DistilBERT, ERNIE — 待收录]

关键演进:
  BERT: 双向上下文 + Masked Language Model
  RoBERTa: 去除 NSP、更大 batch、更多数据 → 本质是"BERT 的正确训练方法"
  ALBERT: 效率优化（参数共享）而非性能天花板突破
  XLNet: 方法论尝试——用排列语言建模统一自回归和自编码
```

**重要说明**: DeBERTa (Microsoft, 2020/2021) 是 BERT 路线的后期重要工作（引入 disentangled attention），但当前 inventory 未收录。DistilBERT (Hugging Face, 2019) 通过知识蒸馏将 BERT 缩小 40% 而保留 97% 性能，亦未收录。

#### 1D. Encoder-Decoder 统一框架

| 论文 ID | 年份 | 核心创新 | 影响力 |
|---------|------|---------|--------|
| 2.2.5 (T5) | 2019 | Text-to-Text 统一框架：所有 NLP 任务统一为"输入文本 → 输出文本"，系统比较预训练目标、架构、数据规模的消融实验。发布 C4 数据集。 | 为后续统一架构（如 FLAN）奠定思想基础 |
| 2.2.6 (BART) | 2019 | 去噪自编码器：用任意噪声函数破坏文本，让模型学习重建。在文本生成（摘要）任务上特别有效。 | Facebook AI 的代表性工作，BART 成为 RAG 的基础模型 |

**阶段小结**: 2018–2019 是 NLP 历史上最富创造力的时期之一。三条架构路线（Encoder-Only、Decoder-Only、Encoder-Decoder）并行发展，但尚未决出最终赢家。到 2019 年底，BERT 家族在理解任务上统治，T5/BART 在生成任务上表现优异，GPT-2 则展示了令人惊叹的零样本文本生成能力。

### Phase 2: 规模化与大一统 (2019–2020)

**核心研究问题**: 如果继续扩大模型和数据规模，会发生什么？性能天花板在哪里？

#### 2A. Scaling Laws：打开规模之门

| 论文 ID | 年份 | 核心发现 | 范式影响 |
|---------|------|---------|---------|
| 2.3.1 (Scaling Laws) | 2020 | **损失 = f(模型规模, 数据量, 计算量)** 遵循幂律关系。在固定计算预算下，大模型 + 少量数据 > 小模型 + 大量数据。 | **直接指导了 GPT-3 的设计**；奠定了"大就是好"的信念 |
| 2.3.2 (GPT-3) | 2020 | 175B 参数模型，展示 Few-Shot In-Context Learning——无需梯度更新即可"理解"示范并完成新任务。 | **范式转变**: 从 "pre-train + fine-tune" 到 "pre-train + prompt" |

**Scaling Laws → GPT-3 的关键推论**:
- Kaplan et al. 建议在给定计算预算下**优先扩大模型而非数据**
- GPT-3 据此设计了 175B 参数、约 300B tokens 的训练方案
- 但这一建议后来被 Chinchilla 推翻（见 Phase 3）

**GPT-3 的涌现能力**:
- 论文标题 "Language Models are Few-Shot Learners" 即核心主张
- 不需要微调，仅通过 prompt 中的少数示例即可完成任务
- 但 Few-Shot 性能不稳定，且远逊于 Fine-Tuning——这是后来的 InstructGPT 要解决的问题

#### 2B. 开源大模型初尝试

| 论文 ID | 年份 | 规模 | 意义 |
|---------|------|------|------|
| 2.3.5 (Gopher) | 2021/2022 | 280B | DeepMind 对 Scaling 的系统性分析：不同任务类别受益于规模化的程度不同 |
| 2.3.7 (OPT) | 2022 | 125M–175B | Meta AI 尝试复现 GPT-3 类性能并完全开源，虽未完全成功，但开启了"复现闭源模型"的先河 |
| 2.3.6 (BLOOM) | 2022/2023 | 176B | 迄今为止最大的完全开源多语言 LLM（46 语言+13 编程语言），由全球 1000+ 研究人员协作 |

### Phase 3: 对齐与推理觉醒 (2021–2022)

**核心研究问题**: 大模型的能力已经有了，但如何让它"听话"？如何让它"思考"？

#### 3A. 对齐路线：让模型遵循人类意图

```
RLHF 理论奠基                         InstructGPT (实用化)               GPT-4 (集大成)
┌──────────────────┐         ┌─────────────────────────┐        ┌──────────────────────┐
│ 2.4.1 Christiano │         │ 2.4.2 Ouyang et al.     │        │ 2.4.3 OpenAI (2023)  │
│ 2017              │  ────→  │ OpenAI, 2022             │ ────→ │ 多模态 + RLHF        │
│ 人类偏好→奖励模型  │         │ SFT + PPO-RLHF           │        │ 未公开规模 (~>1T)     │
│ → PPO 优化策略    │         │ 1.3B > 175B (人类偏好)    │        │ 专业考试人类水平      │
└──────────────────┘         └─────────────────────────┘        └──────────────────────┘
                                        │
                                        │ 分支
                    ┌───────────────────┼───────────────────┐
                    ↓                   ↓                   ↓
            2.4.5 Const.AI      2.4.4 DPO (2023)      2.4.6 FLAN (2021)
            Anthropic, 2022     Stanford            Google
            RLAIF = AI 自己     无需奖励模型的        指令微调 → 零样本泛化
            标注有害输出         偏好优化              在未见任务上超越 GPT-3
```

**RLHF 演进的关键转折**:

| 论文 | 核心问题 | 解决方案 | 局限性 |
|------|---------|---------|--------|
| 2.4.1 (RLHF 2017) | 如何让 AI 的行为符合人类偏好？ | 人类偏好 → 奖励模型 → PPO | 当时仅用于 Atari/机器人，非语言模型 |
| 2.4.2 (InstructGPT) | 大模型输出不符合人类期望（有害、不真实、不相关） | SFT 冷启动 + RLHF 微调 | PPO 训练不稳定，需维护独立的奖励模型 |
| 2.4.4 (DPO) | RLHF 太复杂（4 个模型：policy+ref+reward+value） | 将 RLHF 重新参数化为直接分类损失 | 偏好数据质量要求高；对分布外偏好泛化存疑 |
| 2.4.5 (Constitutional AI) | 人类标注有害内容太昂贵且有心理负担 | AI 自我生成反馈（RLAIF） | 规则设定的完备性无法保证 |

**关键转折点**: DPO (2023) 的出现标志着对齐方法从"强化学习路线"向"直接优化路线"的转变。此后 ORPO (2024, KAIST，待收录) 进一步合并了 SFT 和偏好对齐为单一步骤；KTO (2024, Contextual AI，待收录) 则允许使用非成对偏好数据。

```
│ GSM8K SOTA       │    │ • 2.6.3 ToT      │    │   (2025) 纯RL训练    │
└──────────────────┘    │   树状搜索+回溯    │    │   匹配 o1 性能        │
                        │ • 2.6.7 STaR     │    └──────────────────────┘
                        │   自引导推理提升   │
                        └──────────────────┘
```

**推理方法的层级递进**:

| 层级 | 方法 | 年份 | 核心思想 | 适用场景 |
|------|------|------|---------|---------|
| L0: Prompt-based | CoT (2.6.1) | 2022 | 在 prompt 中加入 "Let's think step by step" | 算术、常识推理 |
| L1: 采样增强 | Self-Consistency (2.6.2) | 2022 | 采样多条推理路径，取多数共识 | 需鲁棒性提升的场景 |
| L2: 搜索增强 | ToT (2.6.3) | 2023 | BFS/DFS 树搜索，支持回溯和剪枝 | 规划、搜索类问题 |
| L2: 行动增强 | ReAct (2.6.4) | 2022 | 推理步骤中交错调用外部工具/行动 | 知识密集型 QA、决策 |
| L3: 训练增强 | STaR (2.6.7) | 2022 | 用模型生成的正确推理链做微调 | 从失败案例中学习 |
| **L4: 推理模型** | **o1 (2.6.6)** | **2024** | **推理时扩展计算：模型内部进行长链式思考** | **数学竞赛、科学推理** |
| **L4: 推理模型** | **DeepSeek-R1 (2.6.5)** | **2025** | **纯 RL 训练（无 SFT 冷启动）激发推理能力；模型自发发展出反思、验证行为** | **数学、代码基准** |

**范式转变**: o1 和 DeepSeek-R1 标志着 **"推理时计算"（test-time compute scaling）成为新维度**。传统 LLM 仅在训练时投入计算、推理时固定成本；o1/R1 在推理时也动态分配计算资源，实现了"思考越久，答案越好"的模式。

#### 3C. Chinchilla：对 Scaling Laws 的修正

| 论文 ID | 年份 | 核心发现 | 与 Kaplan 的关键区别 |
|---------|------|---------|---------------------|
| 2.3.3 (Chinchilla) | 2022 | **模型大小和训练 token 数应等比缩放**。70B Chinchilla 用 4× 数据 (1.4T tokens) 超越 280B Gopher。 | Kaplan: 优先扩大模型 → 导致训练不足；Chinchilla: 同等扩大模型和数据 → 计算最优 |

**对后续模型的深远影响**:
- LLaMA (2023) 明确引用了 Chinchilla 的发现：7B 模型用 1T tokens 训练，13B 用 1T tokens——远超过 Kaplan 建议的比例
- 几乎所有后续开源模型（Mistral, Qwen, DeepSeek）都遵循了 Chinchilla 定律
- Chinchilla 的发现使"小而精"成为可能：不需要天量参数，充分训练的小模型可以超越训练不足的大模型

#### 3D. PaLM：涌现能力的系统论证

| 论文 ID | 年份 | 核心贡献 |
|---------|------|---------|
| 2.3.4 (PaLM) | 2022 | 540B 参数，使用 Pathways 系统在 6144 TPU v4 上训练。在 BIG-bench 上展示了**不连续的涌现**——某些能力在达到特定规模阈值后突然出现。 |

PaLM 是 Google 对 GPT-3 的回应，直接催化了后续 CoT 论文（2.6.1）的实验——Wei et al. 正是在 540B PaLM 上展示了 CoT 的强大效果。

## 4. 关键分叉与融合

### 4.1 Scaling Law 路线

```
Kaplan et al. (2.3.1, 2020)
│  损失 ~ (模型规模)^α × (数据量)^β × (计算量)^γ
│  建议: 在固定计算预算下优先扩大模型
│
├──→ GPT-3 (2.3.2, 2020): 直接应用 Kaplan 建议，175B 参数，~300B tokens
│
├──→ Gopher (2.3.5, 2022): DeepMind 的系统性规模化分析，280B
│
└──→ Chinchilla (2.3.3, 2022): 修正 Kaplan
    │  "模型和数据应等比缩放"  —— 这是范式修正
    │
    ├──→ LLaMA (2.5.1, 2023): 7B 模型用 1T tokens 训练
    │    明确引用 Chinchilla 发现
    │
    ├──→ Mistral 7B (2.5.4, 2023): 同样遵循高数据/参数比
    │
    ├──→ DeepSeek-V3 (2.5.11, 2024): 14.8T tokens 训练 671B MoE
    │    训练成本仅 $5.6M → 极大挑战了"大模型一定贵"的假设
    │
    └──→ 2025 趋势: DeepSeek 的超大 batch + FP8 混合精度 → 新的 Scaling 实践
```

**核心争论**: Kaplan vs Chinchilla 是 LLM 历史上最重要的"科学争论"之一。Kaplan 建议优先扩大模型，导致 GPT-3/PaLM 等模型可能训练不足；Chinchilla 证明更多数据可以弥补模型规模的不足，直接催生了 LLaMA 和"小而美"开源模型运动。

## 5. 影响力路径分析

> 本节对 paper_inventory 中的关键论文进行影响力维度的标注分析。

### 5.1 领域转折点（Paradigm Shift）

这些论文**改变了领域的基本假设或工作方式**：

| 论文 ID | 论文 | 转折点性质 |
|---------|------|-----------|
| 2.1.1 | Transformer (2017) | **架构范式**: 从 RNN/LSTM 到全自注意力，定义了整个深度学习后续架构 |
| 2.2.2 | BERT (2018) | **训练范式**: "预训练+微调"成为 NLP 标配，双向上下文表示取代单向 |
| 2.3.2 | GPT-3 (2020) | **交互范式**: In-Context Learning 证明大模型可以"理解" prompt 而非微调 |
| 2.4.2 | InstructGPT (2022) | **对齐范式**: RLHF 使模型从"能说话"变为"会听话"，直接催生 ChatGPT |
| 2.3.3 | Chinchilla (2022) | **规模化范式**: 修正 "越大越好" 为 "模型+数据等比缩放"，指导后续所有开源模型 |
| 2.5.1 | LLaMA (2023) | **开源范式**: 证明仅用公开数据可匹敌闭源，引爆开源 LLM 运动 |
| 2.4.4 | DPO (2023) | **对齐简化**: 将对齐从复杂 RL 简化为直接分类，降低对齐门槛 |

### 5.2 工程集大成者

这些论文**不一定有根本性方法创新，但通过系统性工程优化达到了 SOTA**：

| 论文 ID | 论文 | 集成性质 |
|---------|------|---------|
| 2.2.4 | RoBERTa (2019) | 系统复现 BERT 并发现"BERT 远未被充分训练"——去掉 NSP、更大 batch、更多数据 |
| 2.3.4 | PaLM (2022) | Google 工程巅峰：6144 TPU v4 训练 540B 模型，系统性展示涌现 |
| 2.4.3 | GPT-4 (2023) | OpenAI 的工程集大成：多模态 + 对齐 + 规模化，但核心方法未完全公开 |
| 2.5.3 | Llama 3 (2024) | Meta 的工程集大成：15T tokens 训练，128K 上下文，多语言，开源标杆 |
| 2.5.11 | DeepSeek-V3 (2024) | 极致效率的工程集大成：FP8 训练，$5.6M 成本，匹敌 GPT-4o |

### 5.3 社区跟随引爆点

这些论文**引发了大量的下游工作和社区跟进**：

| 论文 ID | 论文 | 引爆的跟随方向 |
|---------|------|--------------|
| 2.2.2 | BERT (2018) | → RoBERTa, ALBERT, XLNet, DistilBERT, ERNIE... |
| 2.3.2 | GPT-3 (2020) | → OPT, BLOOM, 各垂直领域 Few-Shot 应用 |
| 2.6.1 | CoT (2022) | → Self-Consistency, ToT, ReAct, STaR, o1, R1... |
| 2.7.4 | LoRA (2021) | → QLoRA, VeRA, DoRA, 各种 PEFT 变体 |
| 2.5.1 | LLaMA (2023) | → Alpaca, Vicuna, WizardLM, Gorilla, 几乎所有开源衍生模型 |
| 2.5.4 | Mistral 7B (2023) | → Notus, Zephyr, Dolphin 等社区微调；GQA/SWA 被广泛采用 |

### 5.4 被后来者超越或修正

| 论文 ID | 论文 | 被如何超越/修正 |
|---------|------|---------------|
| 2.3.1 | Scaling Laws (Kaplan, 2020) | Chinchilla (2.3.3) 修正了"优先扩大模型"的建议 |
| 2.2.8 | XLNet (2019) | 排列语言模型的复杂度/收益比不如直接扩大 RoBERTa |
| 2.2.7 | ALBERT (2019) | 参数共享降低容量，在生成式 LLM 时代影响力减弱 |
| 2.4.2 | InstructGPT / PPO-RLHF | DPO (2.4.4) 以更简单的实现匹配或超越效果 |
| 2.3.7 | OPT (2022) | 未完全复现 GPT-3 性能，被 LLaMA 超越 |
| 2.1.2 | ULMFiT (2018) | BERT 和 GPT-1 的出现使其方法论影响被融入更大的范式 |

### 5.5 争议或被高估

| 论文 / 方向 | 争议性质 |
|------------|---------|
| GPT-3 的涌现能力 | "涌现"是否只是评估指标的非线性（而非模型能力的非线性）存在持续争论 |
| RLHF 的可扩展性 | 人工偏好标注成本高，偏好漂移问题未解决；DPO/RLAIF 试图克服 |
| Scaling Laws 的普适性 | DeepSeek-V3 以极低成本达到高水平，挑战了"更强=更贵"的假设 |
| BERT 的 Encoder-Only 路线 | 在生成式 AI 浪潮中，Encoder-Only 路线的长期影响力在下降 |

## 9. 开问题与未来方向

### 9.1 当前未解决的问题

| 问题 | 描述 | 相关证据 |
|------|------|---------|
| **推理成本** | o1/R1 类推理模型回答一个问题消耗远超标准 LLM 的 token 和时间 | o1 (2.6.6), DeepSeek-R1 (2.6.5) 的推理时计算扩展 |

| **推理可解释性** | DeepSeek-R1 的推理链虽可观察，但模型"为什么这样思考"仍不透明 | DeepSeek-R1 (2.6.5) |
| **评估饱和** | 主流 benchmark 被迅速饱和，新 benchmark 的开发速度跟不上 | 各阶段 benchmark 演进 |
| **数据墙** | Chinchilla 定律要求的数据量已经逼近互联网高质量文本上限 | Chinchilla (2.3.3) 的理论 + Llama 3 使用 15T tokens |
