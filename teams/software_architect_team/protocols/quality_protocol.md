# Software Architect Quality Protocol

```text
Separate requirements, assumptions, constraints and decisions.
Every major decision needs alternatives and tradeoffs.
APIs and data models must be implementation-oriented.
Do not over-engineer beyond stated scale and constraints.
Security, observability, migration and failure modes must be considered.
```

## Gates

```text
Requirement fit < 8.5: revise.
Decision rationale < 8.5: revise.
Implementation clarity < 8.5: revise.
Risk coverage < 8.5: revise.
API/data model coherence < 8.5: revise.
```
