# PPT Writer Team Quality Protocol

## 1. 核心质量目标

```text
1. 可编辑交付：最终必须是 editable .pptx，不能只输出图片、PDF 或 Markdown。
2. 目标清晰：每份 PPT 必须服务一个明确受众和沟通目标。
3. 素材可追溯：关键事实、数据、引用必须能回到 Boss 素材或搜索来源。
4. 结构有叙事：不是素材堆叠，而是有问题、洞察、证据、结论和行动。
5. 页面有单点：每页只承载一个主张或一个清晰任务。
6. 图表有意图：图表不是装饰，必须回答一个问题。
7. 风格一致：字体、色彩、版式、图表样式、间距和层级统一。
8. 模板保真：有模板时必须遵从模板布局、字体、背景、页眉页脚、母版节奏和组件语言；模板不是单纯灵感板。
9. 不伪造事实：素材没有的数据不得编造；推断必须标注为推断。
10. 可复修：必须保留 deck_spec.json，方便二次编辑和重新生成。
11. 图片可交付：需要图片时必须使用本地 prepared image，并保留来源与处理 manifest。
12. 视频可交付：需要视频时必须插入本地视频、缩略图+链接或清晰链接卡片，并保留来源与版权风险记录。
```

## 2. 输入情形

```text
有素材 + 有模板：
  解析素材，解析模板，按模板页面结构和视觉约束生成新内容。

有素材 + 无模板：
  解析素材，根据主题、受众和行业设计视觉系统。

无素材 + 有模板：
  先搜索公开资料，再按模板页面结构和视觉约束生成新内容。

无素材 + 无模板：
  先搜索资料，再设计视觉系统。
```

## 3. PPT 内容门禁

```text
每页必须有：
  slide purpose
  headline
  body or visual intent
  evidence/source note
  speaker note

每章必须有：
  章节目标
  信息推进
  过渡逻辑

整份 PPT 必须有：
  开场上下文
  核心洞察
  证据链
  结论或行动建议
```

## 4. 可编辑 PPT 门禁

```text
标题、正文、标签、脚注、备注必须尽量使用 PPT 原生文本框。
表格应使用 PPT 原生表格或可编辑形状组合。
图表若无法生成原生 chart，必须保留 chart_data.json 或 chart_spec，便于重建。
图片必须来自本地 image_path/processed_path，不能要求作者手动下载插入。
视频必须来自 video_path 或 video_url；若不能嵌入本地视频，必须插入缩略图+可点击链接。
不得把整页渲染成一张图片作为最终交付。
模板解析失败时必须报告限制，并退化为自建设计系统。
编码失败时不得伪称完成，必须输出错误、依赖缺口和修复建议。
```

## 5. 模板遵从门禁

```text
有模板时，template/template_fidelity_plan.md 必须存在。
style_spec.json 必须记录 template_pptx 和 template_fidelity。
页面尺寸、字体、背景、页眉页脚、页码、边距和主要组件样式必须与模板一致或有明确例外。
每页必须映射到模板页面类型或说明为什么需要新增布局。
不得仅提取颜色后重新设计另一套 PPT。
不得复制模板里的无关业务内容、客户名、数据、口号或图表。
```

## 6. 返修门禁

```text
内容准确性 < 9.0：必须返修事实、来源和数据表达。
结构清晰度 < 8.5：必须重排章节或页面顺序。
页面可读性 < 8.5：必须重写标题、压缩文字或调整布局。
视觉一致性 < 8.0：必须重设风格系统或版式规则。
模板遵从性 < 9.0：有模板时必须返修 layout/style spec 或重新编码。
媒体完整性 < 9.0：必须补齐图片/视频下载、插入、链接和来源记录。
可编辑性 < 9.0：必须重新编码 PPTX。
Boss 关键要求未覆盖：必须返修。
```
